**Product Ecosystem**: TRUSTIT — India's Hyper-Local Multi-Service Trust & Commerce Super App  
**Architecture Target**: Multi-App Monorepo / Next.js (App Router), Supabase Auth & Database, Cashfree Payments, Deployed on Vercel  
**Design System**: Kinetic Trust (Plus Jakarta Sans, `#0d47a1` Primary, Light Surface Palette, 8px Roundness)  
**Date**: October 2026  
**Document Classification**: Frontend Engineering & Architecture Handoff

## 1. Executive Architecture & Tech Stack Alignments

This handoff specification upgrades the TRUSTIT design architecture into actionable engineering contracts for engineering teams. All frontend codebases must align with the production stack:

- **Framework**: Next.js 15+ (App Router, Server Components where applicable, Client Components for interactive workflows, Turbopack)
- **Deployment & Hosting**: Vercel (Edge Middleware for auth/geo-routing, Vercel Blob/Edge Functions)
- **Authentication & Database**: Supabase (Supabase Auth with Phone OTP & RLS-enforced PostgreSQL tables, Supabase Realtime for order tracking & chat)
- **Payment Gateway**: Cashfree Payments SDK (Cashfree PG Web/React SDK, UPI Intent, Webhook reconciliations)
- **Styling & Design Tokens**: Tailwind CSS v3.4+ mapped to `Kinetic Trust` CSS variables
- **State Management & Data Fetching**: TanStack Query (React Query) v5 for server-state caching, optimistic updates, and offline sync; Zustand for client-side ephemeral state (cart, active filters, location session).

> **Architectural Guardrail**: Do not invent private database schemas or internal backend signatures. Unknown schema fields, tables, endpoints, and RPC procedures are explicitly flagged as `[NEEDS CODEBASE VERIFICATION]`.

## 4. Role-Based Access Control (RBAC) Specification

| User Role | Permitted Routes & Surfaces | Auth Provider & Verification | Supabase RLS Policy Concept |
|---|---|---|---|
| **Customer** | `/(tabs)/*`, `/checkout`, `/order-*`, `/addresses`, `/support`, `/notifications` | Supabase Phone Auth OTP (`+91`) | Reads public catalogs, reads/updates only own `user_id` orders, addresses, and reviews. |
| **Merchant Admin** | `/merchant/*` | Supabase Auth (Email + Mobile OTP) with role claim `merchant_admin` | Reads/writes only data matching `merchant_id` foreign key. Restricted from user payment credentials. |
| **Rider / Technician** | `/rider/*` | Supabase Auth (Rider Mobile) with role claim `rider_partner` | Assigned orders read/write state transitions (`ACCEPTED`, `ARRIVED_STORE`, `OUT_FOR_DELIVERY`, `DELIVERED`). |
| **Platform Ops Admin** | `/admin/*` | Supabase Auth with Hardware MFA / TOTP and role claim `super_admin` or `compliance_auditor` | Full system audit capabilities across escrow, merchant KYC, and dispute resolution. |

#### C-02: Mobile Login & OTP Verification

## 8. Cashfree Payment & Order Lifecycle State Machine

```
[ ORDER CREATED ] (Idempotency Key Generated)
       │
       ▼
[ PAYMENT INITIATED ] (Cashfree Web / Intent SDK Handshake)
       │
       ├─────────────────────────────────┐
       ▼ (Gateway Error / Drop-off)      ▼ (Bank Authorization Succeeded)
[ PAYMENT FAILED ]                 [ AUTHORIZED / ESCROW HELD ]
 (Inventory locked 08:42 mins)           │
       │                                 ▼
 (Failover Gateway / Retry)        [ ORDER ACCEPTED BY MERCHANT ]
                                         │
                                         ▼
                                   [ PREPARING ORDER ]
                                         │
                                         ▼
                                   [ OUT FOR DELIVERY ] (Rider Assigned)
                                         │
                                         ▼
                                   [ DOORSTEP HANDOVER OTP ] (PIN: 4821)
                                         │
                                         ▼
                                   [ ORDER COMPLETED & SETTLED ]
                                         │
                                         ▼
                                   [ VERIFIED REVIEW UNLOCKED ]
```

## 9. Security, Compliance & DPDP Act 2023 Implementation

1. **OTP & Doorstep PIN Masking**:
   - The Doorstep Handover PIN (`4821`) must **never** be included in push notification preview payloads or open metadata.
   - PIN is stored hashed or encrypted on client and decoded only when the customer views the active tracking view.
2. **Phone Number Masking**:
   - Customer and rider phone numbers must be routed through telephony bridge proxies. Raw telephone numbers are omitted from client-side JSON payloads.
3. **DPDP Act 2023 Compliance**:
   - Every customer retains the right to data portability and complete account deletion via `/profile`.
   - Explicit consent toggles for WhatsApp transaction pings and location tracking are persisted in `user_consents` table `[NEEDS CODEBASE VERIFICATION]`.
4. **Schedule H/H1 CDSCO Compliance**:
   - Prescription images stored in Supabase Storage must use private signed URLs with maximum 15-minute expiration.
   - Orders containing Schedule H medications are locked from fulfillment until a registered pharmacist signs off via Admin/Merchant desk.

## 10. Accessibility (a11y) & Performance Engineering

- **Touch Targets**: Min 48px × 48px touch targets across all mobile apps (especially Rider App for outdoor use).
- **Color Contrast**: 4.5:1 minimum contrast ratio for text elements against light surface `#faf8ff`.
- **Screen Reader Support**: All icons must have descriptive `aria-label` tags (e.g. `aria-label="Verified FSSAI License"`).
- **Core Web Vitals**: Target LCP < 1.8s on 4G networks; dynamic image imports using Next.js `<Image />` with AVIF/WebP formats and responsive `sizes` attribute.
