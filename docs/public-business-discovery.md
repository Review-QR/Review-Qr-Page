# Public business discovery

Public routes are server rendered at `/[city]/[category]` and `/[city]/[category]/[businessSlug]`. Both routes use the service-role-only `get_public_trustit_businesses` RPC and the server sanitizer in `lib/public-discovery.ts`. The RPC is the eligibility boundary; it requires a non-deleted business, `status` active or expiring soon, active merchant and QR states, and a null or non-expired subscription date. A location must be confirmed, have a nonblank city/state and six-digit pincode, and match the requested city. Locality, district, and coordinates are optional.

The public aggregate counts only rows where `trustit_reviews.status`, `review_sessions.review_status`, and `review_sessions.trustit_status` all indicate submitted. It returns count, average, and a last-submission timestamp used only by server-side ranking. It never returns review text or customer information. Google review links pass HTTPS and Google-host checks before display.

Business slugs are stored separately from business IDs. The initial migration backfills all existing IDs in ID order and gives duplicates numeric suffixes. An insert trigger uses the same collision-safe scheme, protected by a transaction advisory lock. Renaming a business does not change its slug. The `/r/[id]` route remains separate and unchanged.

Merchants confirm location from My Business; active administrators can review and mark a business location as admin reviewed from Business Management. Both actions update structured location fields only, preserving the registered address and GPS coordinates. A separate verification timestamp, actor, and source record the confirmation. Editing structured location through an older profile RPC clears that marker until the location is confirmed again. Existing business locations are not backfilled or inferred from address text.

Recommended ranking uses a Bayesian mean with prior mean 4 and prior weight 5: `(average * reviewCount + 4 * 5) / (reviewCount + 5)`. Confidence is `reviewCount / (reviewCount + 5)`. Recency uses a 365-day half-life. Profile completeness counts only address, locality, city, and coordinates that exist. When customer coordinates exist, proximity decays exponentially with a 10 km scale. Search relevance favors exact name, name prefix, and name substring; exact city/category are enforced as filters. The weighted score is `0.62 adjusted rating + 0.20 confidence + 0.05 recency + 0.05 completeness + 0.03 proximity + 0.05 search relevance`, with rating and confidence tie-breakers, then review recency, distance, and stable business ID.

Production currently has no structured city values, so listing routes return an honest empty state until merchants add cities. No free-text address parsing is performed. Photos, hours, descriptions, products, specialties, and public Trustit review text are not displayed because no approved data source exists.
